# Net Arcade

네트워크구조및설계 강의의 Quick Check 문항을 미니게임으로 클리어하는 학습용 아케이드.

각 게임은 스테이지를 끝낼 때마다 결산 화면에서 그 스테이지에 걸린 Quick Check 문항을 낸다. 정답을 고르면 허브의 Quick Check 지도에 클리어로 기록된다. 기록은 브라우저 localStorage에만 저장된다.

## 실행

설치할 것은 없다. `index.html`을 브라우저로 열면 된다.

폰트나 저장이 이상하면 로컬 서버로 연다.

```
python -m http.server 8000
```

그다음 http://localhost:8000 에 접속한다.

## 게임 현황

기본 게임은 시간 제한이 없는 턴제다(택배 발송 사무소만 여유 있는 타이머). 첫 판은 따라하기 튜토리얼이고, 행동할 때마다 해설이 나온다.

| 게임 | 주차 | 원형 | 상태 | Quick Check |
|---|---|---|---|---|
| 우체국 분류소 | 2 | Papers, Please (턴제) | 플레이 가능 | W2-1, W2-2, W2-4 |
| AI 서비스 노선도 | 1 | 미니 메트로 (턴제) | 플레이 가능 | W1-1 ~ W1-5 |
| 주소 블록 퍼즐 | 2 | 블록 블라스트 | 플레이 가능 | W2-2 |
| 패킷 여행 보드게임 | 2 | 말판 보드게임 (주사위·관문) | 플레이 가능 | W2-3 ~ W2-6 |
| TCP 메신저 | 3 | 메신저 대화 (패킷 조립) | 플레이 가능 | W3-1, W3-8 |
| 패킷 솔리테어 | 3 | 카드 솔리테어 | 플레이 가능 | W3-7, W3-6 |
| 택배 발송 사무소 | 3 | 파파스 피자리아 (여유 타이머) | 플레이 가능 | W3-7, W3-10, W3-6 |
| 혼잡 제어 블랙잭 | 3 | 블랙잭 (카지노 연출) | 플레이 가능 | W3-6, W3-2, W1-1 |
| 소켓 식당 | 3 | 턴제 식당 경영 | 플레이 가능 | W3-2 ~ W3-5 |
| DNS 마을 탐험 | 4 | 지도 이동 RPG (NPC 대화) | 플레이 가능 | W4-1 ~ W4-3 |
| HTTP 공방 & 보안 검문소 | 4 | 조립 퍼즐 + 서류 심사 | 플레이 가능 | W4-4, W4-5, W4-7 ~ W4-9, W2-7 |
| 네트워크 역전재판 | 3·4 | 역전재판 (증거 제시 추리) | 플레이 가능 | W3-9, W3-10, W4-6, W4-10 |
| 프로토콜 산성비 | 1~4 | 한컴타자 산성비 (실시간 · 무한 모드) | 플레이 가능 | 복습용 (문제 무작위 생성) |
| 패킷 닌자 | 2~4 | 과일닌자 (실시간 · 무한 모드) | 플레이 가능 | W2-7 (방화벽 규칙, 문제 무작위 생성) |
| 핸드셰이크 비트 | 3 | 리듬게임 (실시간 · 무한 모드) | 플레이 가능 | W3-1, W3-8 (TCP 상태, 사건 무작위) |

무한 모드 게임(`mode: 'endless'`)은 허브의 "∞ 무한 모드" 탭에 따로 모인다. 무한 모드 설명은 탭에 들어갈 때 팝업으로 뜨고(다시 띄우지 않기 선택 가능), 탭 옆 "ⓘ 무한 모드란?" 버튼으로 언제든 다시 볼 수 있다. 기존 게임 중 우체국 분류소, 혼잡 제어 블랙잭, 택배 발송 사무소는 스테이지 목록 끝에 **∞ 무한 모드**가 있고(`qc-data.js`의 `endless` 설명), 무한 모드 탭에서 바로 들어갈 수 있다(`#endless`). 공통 부품은 `NA.ui.stageMenu({ endless })`, `NA.ui.debrief({ endless: true })`, `NA.wantsEndless()`.

32문항 전체와 게임 매핑은 [docs/QUICK_CHECK.md](docs/QUICK_CHECK.md). 기획 중인 게임의 설계는 각 `games/<id>/README.md`.

## 한 파일로 공유하기

```
python tools/build_single.py
```

`dist/net-arcade.html` 하나가 만들어진다(약 2.3 MB). 허브, 플레이 가능한 모든 게임, 폰트가 전부 들어 있어서 이 파일만 보내면 받는 사람이 더블클릭으로 바로 플레이할 수 있다. 게임을 고치거나 새로 만든 뒤에는 다시 실행한다. `dist/`는 빌드 결과물이라 git에 올리지 않는다.

## 구조

```
net-arcade/
├── index.html              허브: 게임 목록 + Quick Check 지도
├── shared/
│   ├── base.css            공통 스타일
│   ├── engine.js           캔버스 루프, 입력, 효과음, 파티클 (외부 라이브러리 없음)
│   ├── ui.js               진행도 저장, 스테이지 메뉴, Quick Check 결산 화면
│   ├── qc-data.js          Quick Check 32문항 + 게임 목록 (단일 출처)
│   └── fonts/              Galmuri11 (SIL OFL 1.1)
├── games/
│   └── <game-id>/
│       ├── index.html
│       ├── game.js
│       └── README.md
├── tools/
│   ├── build_single.py     한 파일 HTML 빌드
│   └── gen_qc_doc.js       docs/QUICK_CHECK.md 생성
└── docs/
    └── QUICK_CHECK.md
```

모든 스크립트는 일반 `<script>`라서 빌드 없이 `file://`로 열어도 동작한다.

모든 화면은 1280×720으로 설계되어 있고, `NA.fitStage`가 창 크기에 맞게 확대·축소한다. 그래서 페이지 스크롤이 생기지 않는다. 새 게임도 이 크기 안에 배치한다.

## 새 게임 추가

1. `games/post-office/`(DOM 기반 턴제)를 `games/<새 id>/`로 복사한다. 캔버스 실시간 게임이 필요하면 `shared/engine.js`의 `NA.createGame`을 쓴다.
2. 제목과 `GAME_ID`, 스테이지 목록을 바꾼다. 스테이지마다 `qc: ['W?-?']`를 지정하면 결산 화면에 그 문항이 나온다.
3. `shared/qc-data.js`의 `NA.GAMES`에서 해당 게임의 `ready`를 `true`로 바꾼다.
4. `node tools/gen_qc_doc.js`로 `docs/QUICK_CHECK.md`를 다시 만든다.

## 깃 작업 흐름 (제안)

- `main`: 플레이 가능한 상태만 둔다
- `game/<id>`: 게임 하나를 만드는 브랜치
- 커밋 단위: 스테이지 하나, 또는 메커닉 하나
- 배포: GitHub Pages (Settings → Pages → main / root)를 켜면 링크 하나로 폰에서도 플레이할 수 있다
