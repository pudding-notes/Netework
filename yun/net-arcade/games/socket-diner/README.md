# 소켓 식당

상태: 플레이 가능

- 주차: Week 3
- 원형: 턴제 식당 경영
- Quick Check: W3-2, W3-3, W3-4, W3-5

## 비유

식당 = 서버 프로세스, 문 번호 = 포트(:443), 입구 안내원 = listen 소켓(fd 3), 줄 = accept 큐(backlog), 전담 테이블 = 연결 소켓(accept()마다 새 fd), 손님 명찰 = 4-tuple, 우편함 = 도착한 패킷. 나는 커널 겸 지배인.

## 핵심 플레이

- 개업 준비: 시스템 호출 카드를 순서대로 누른다 (socket → bind → listen → accept → recv/send → close). connect()는 함정
- 영업: 턴마다 우편함에 SYN·주문·FIN 패킷이 온다. 끌어다(또는 눌러서) 알맞은 소켓에 놓는다
  - SYN → 입구 안내원. 커널이 handshake를 끝내고 줄에 세운다. 줄이 꽉 차면 손님이 돌아간다
  - accept()로 줄 맨 앞 손님에게 테이블(가장 작은 빈 fd)을 내준다
  - 주문·FIN → 4-tuple이 같은 테이블. 떠난 손님 테이블은 close(). 두 턴 넘게 방치하면 CLOSE_WAIT 경고
- 배정: 주문을 TCP 정식 홀 / UDP 테이크아웃 창구로 끌어다 놓는다
- 틀리면 신뢰도 −1(5칸), 그 자리에서 해설

## 스테이지

1. 개업 준비: 서버 시스템 호출 순서, accept()의 역할 (W3-5)
2. 첫 영업: 안내원은 새 손님만, 주문은 테이블로 (W3-5)
3. 같은 문, 다른 명찰: 같은 IP 다른 포트, 다른 IP 같은 포트를 4-tuple로 구분 (W3-4)
4. 소켓 세기: backlog 2칸 러시, 포트 1개 vs 소켓 N+1개 (W3-3)
5. 정식 vs 테이크아웃: TCP와 UDP 배정, "UDP가 빠르다"의 의미 (W3-2)
