# Quick Check 지도

강의자료 마지막 장의 Quick Check 32문항과 그 문항을 클리어하는 게임. 이 문서는 shared/qc-data.js 내용을 옮긴 것이다. 문항을 고칠 때는 qc-data.js를 고친다.

## Week 1

- **W1-1** "인터넷 속도가 1 Gbps면 latency도 항상 낮다." 맞을까?
  - 게임: AI 서비스 노선도, 혼잡 제어 블랙잭
  - 정답: 틀리다. 1 Gbps는 대역폭(초당 실어 나르는 양)이고, latency는 거리(전파 지연)·홉 수·큐 대기가 정하는 지연 시간이다(왕복이면 RTT).
- **W1-2** "Cloud는 인터넷 어딘가에 있는 다른 사람의 컴퓨터"라고만 이해해도 충분할까?
  - 게임: AI 서비스 노선도
  - 정답: 부족하다. 위치뿐 아니라 필요할 때 자원을 늘리고 줄이는 운영 모델(가상화·자동 확장·관리형 서비스)까지 포함한다.
- **W1-3** "Client와 Server는 장치 종류가 아니라 통신에서의 역할이다." 맞을까?
  - 게임: AI 서비스 노선도
  - 정답: 맞다. 같은 PC도 요청을 보내면 클라이언트, 요청을 받아 서비스하면 서버다.
- **W1-4** "Edge computing은 Cloud를 완전히 대체하는 기술이다." 맞을까?
  - 게임: AI 서비스 노선도
  - 정답: 틀리다. Edge는 지연·대역폭이 중요한 처리를 가까이서 하고, 저장·학습·집계는 여전히 Cloud가 맡는 보완 관계다.
- **W1-5** "AI 서비스도 결국 네트워크를 통해 request와 response를 주고받는다." 맞을까?
  - 게임: AI 서비스 노선도
  - 정답: 맞다. 프롬프트는 HTTP 요청으로 API 서버에 가고, GPU 추론 결과가 응답으로 돌아온다.

## Week 2

- **W2-1** 192.168.1.20/24와 192.168.2.20/24는 같은 subnet인가?
  - 게임: 우체국 분류소
  - 정답: 다르다. /24면 앞 24비트(192.168.1 vs 192.168.2)가 네트워크 부분인데 서로 다르다.
- **W2-2** 192.168.10.0/26의 Broadcast 주소와 사용 가능한 Host 수는?
  - 게임: 우체국 분류소, 주소 블록 퍼즐
  - 정답: Broadcast 192.168.10.63, Host 62개. 2^(32−26) = 64개 중 네트워크·브로드캐스트 주소 2개를 뺀다.
- **W2-3** 127.0.0.1:8000에서 127.0.0.1과 8000은 각각 무엇을 식별하는가?
  - 게임: 패킷 여행 보드게임
  - 정답: 127.0.0.1은 호스트(내 PC 자신, loopback)를, 8000은 그 안의 프로세스(서비스)를 식별한다.
- **W2-4** Default Gateway가 필요한 경우는 언제인가?
  - 게임: 우체국 분류소, 패킷 여행 보드게임
  - 정답: 목적지 IP가 내 subnet 밖일 때. 같은 subnet이면 ARP로 직접 보내고, 아니면 Gateway(라우터)에게 넘긴다.
- **W2-5** 패킷이 Router를 지날 때 바뀌는 주소는 IP인가 MAC인가?
  - 게임: 패킷 여행 보드게임
  - 정답: MAC. MAC은 다음 홉 장비를 가리키므로 홉마다 바뀌고, IP는 최종 목적지라 (NAT가 없으면) 끝까지 유지된다.
- **W2-6** Private IP를 가진 PC가 Internet에 접속할 수 있는 이유는?
  - 게임: 패킷 여행 보드게임
  - 정답: 공유기의 NAT(PAT)가 출발지 사설 IP:포트를 공인 IP:포트로 바꿔 내보내고, 응답은 NAT 테이블을 보고 되돌려 주기 때문이다.
- **W2-7** 0.0.0.0에 bind한다는 것은 Public Internet에 자동 공개된다는 뜻인가?
  - 게임: HTTP 공방 & 보안 검문소
  - 정답: 아니다. 0.0.0.0은 "이 PC의 모든 인터페이스에서 받겠다"는 뜻일 뿐이고, 외부 공개 여부는 NAT·방화벽·Security Group이 정한다.

## Week 3

- **W3-1** 3-way handshake는 왜 3번인가? 2번으로는 무엇이 부족한가?
  - 게임: TCP 메신저
  - 정답: 양쪽 모두 상대가 자기 초기 순서번호(ISN)를 받았다는 확인이 필요하다. 2번이면 서버의 ISN이 확인되지 않고, 지연된 옛 SYN에도 연결이 열려 버린다.
- **W3-2** "UDP가 빠르다"는 표현은 어떤 의미에서 맞고 어떤 의미에서 틀린가?
  - 게임: 혼잡 제어 블랙잭, 소켓 식당
  - 정답: 핸드셰이크·재전송 대기·HOL 블로킹이 없어 지연이 작다는 점은 맞다. 처리량이 더 크다는 뜻은 아니고, 유실·순서·혼잡 제어를 앱이 떠안는다.
- **W3-3** Socket과 Port의 차이를 한 문장으로 설명하라.
  - 게임: 소켓 식당
  - 정답: Port는 호스트 안의 서비스를 가리키는 16비트 번호이고, Socket은 프로세스가 (프로토콜, IP, Port)에 묶어 실제로 읽고 쓰는 OS 객체(손잡이)다.
- **W3-4** TCP 연결은 무엇으로 식별되는가? 같은 서버 포트에 여러 연결이 가능한 이유는?
  - 게임: 소켓 식당
  - 정답: 4-tuple(출발지 IP, 출발지 Port, 목적지 IP, 목적지 Port)로 식별된다. 서버 포트가 같아도 클라이언트 쪽 IP·Port가 달라서 구분된다.
- **W3-5** listen 소켓과 연결 소켓은 어떻게 다른가? accept()가 하는 일은?
  - 게임: 소켓 식당
  - 정답: listen 소켓은 새 연결 요청만 받는 접수처다. accept()는 핸드셰이크가 끝난 연결을 큐에서 꺼내 그 클라이언트 전용 연결 소켓을 새로 만들어 돌려준다.
- **W3-6** Flow control과 Congestion control은 각각 무엇을 보호하는가?
  - 게임: 패킷 솔리테어, 택배 발송 사무소, 혼잡 제어 블랙잭
  - 정답: Flow control은 수신자(수신 버퍼)를, Congestion control은 네트워크(병목 라우터의 큐)를 보호한다.
- **W3-7** 누적 ACK에서 중복 ACK가 반복되면 송신자는 무엇을 알게 되는가?
  - 게임: 패킷 솔리테어, 택배 발송 사무소
  - 정답: 중간 세그먼트 하나가 빠졌지만 그 뒤 세그먼트들은 계속 도착하고 있다는 것. 중복 ACK 3개면 타임아웃 전에 빠른 재전송을 한다.
- **W3-8** TIME_WAIT과 CLOSE_WAIT 중 코드 버그의 신호는 어느 쪽인가? 왜?
  - 게임: TCP 메신저
  - 정답: CLOSE_WAIT. 상대가 FIN을 보냈는데 내 코드가 close()를 호출하지 않아 남는 상태다. TIME_WAIT은 먼저 닫은 쪽의 정상 대기다.
- **W3-9** Connection refused와 Connection timed out은 조사 방향이 왜 다른가?
  - 게임: 네트워크 역전재판
  - 정답: refused는 호스트까지 갔지만 그 포트에 listen이 없어 RST가 온 것(서비스·포트·bind 확인)이고, timeout은 응답 자체가 없는 것(경로·방화벽·호스트 상태 확인)이다.
- **W3-10** "연결은 되는데 느리다"를 만났을 때 무엇부터 측정할 것인가?
  - 게임: 택배 발송 사무소, 네트워크 역전재판
  - 정답: RTT(지연)와 처리량부터 재서 지연 문제인지 대역폭·손실 문제인지 나눈다. 그다음 재전송, 윈도우, 서버 처리 시간을 본다.

## Week 4

- **W4-1** URL과 Domain의 차이는? DNS는 URL의 어느 부분만 아는가?
  - 게임: DNS 마을 탐험
  - 정답: URL은 scheme·host·port·path·query·fragment를 모두 포함한 주소이고 Domain은 그중 host다. DNS는 host만 안다.
- **W4-2** 재귀 질의와 반복 질의는 각각 누구와 누구 사이에서 일어나는가?
  - 게임: DNS 마을 탐험
  - 정답: 재귀 질의: 클라이언트(stub) ↔ 재귀 리졸버("최종 답을 달라"). 반복 질의: 리졸버 ↔ root·TLD·권한 서버("다음에 물어볼 곳을 알려 달라").
- **W4-3** DNS 레코드를 바꿨는데 일부 사용자만 옛 서버로 가는 이유는?
  - 게임: DNS 마을 탐험
  - 정답: 리졸버·OS·브라우저 캐시에 옛 레코드가 TTL이 끝날 때까지 남아 있기 때문이다.
- **W4-4** HTTP 메시지에서 헤더와 본문의 경계는 무엇으로 구분되는가?
  - 게임: HTTP 공방 & 보안 검문소
  - 정답: 빈 줄(\r\n\r\n). 본문이 어디서 끝나는지는 Content-Length 등으로 안다.
- **W4-5** PUT은 멱등인데 POST는 아닌 이유는? 재시도와 어떤 관계인가?
  - 게임: HTTP 공방 & 보안 검문소
  - 정답: PUT은 "이 자원을 이 상태로"라서 여러 번 보내도 결과가 같다. POST는 "새로 하나 만들어"라서 재시도하면 중복 생성될 수 있다. 그래서 POST 재시도에는 멱등 키가 필요하다.
- **W4-6** 404와 502는 각각 누가 만든 응답인가?
  - 게임: 네트워크 역전재판
  - 정답: 404는 원본 서버(앱)가 "그 자원이 없다"고 만든 응답이다. 502는 프록시·게이트웨이가 "뒤쪽 서버에게서 정상 응답을 못 받았다"고 만든 응답이다.
- **W4-7** HTTP/2가 해결한 것과 해결하지 못해 HTTP/3가 나온 이유는?
  - 게임: HTTP 공방 & 보안 검문소
  - 정답: HTTP/2는 한 연결에 여러 스트림을 섞어 HTTP 계층의 HOL 블로킹을 없앴다. 하지만 TCP 하나 위라서 패킷 하나만 유실돼도 모든 스트림이 멈춘다. HTTP/3는 QUIC(UDP 위)으로 스트림별 독립 전송을 한다.
- **W4-8** HTTPS에서 암호화되는 것과 여전히 보이는 것은?
  - 게임: HTTP 공방 & 보안 검문소
  - 정답: 암호화되는 것: path·query, 헤더, 쿠키, 본문. 여전히 보이는 것: 목적지 IP·포트, 도메인(DNS 질의·SNI), 트래픽 크기와 타이밍.
- **W4-9** 브라우저는 인증서에서 어떤 항목들을 검증하는가?
  - 게임: HTTP 공방 & 보안 검문소
  - 정답: 도메인 일치(SAN), 유효기간, 신뢰하는 Root CA까지 이어지는 서명 체인, 폐기 여부.
- **W4-10** DevTools에서 TTFB만 길다면 무엇을 의심해야 하는가?
  - 게임: 네트워크 역전재판
  - 정답: DNS·TCP·TLS 구간은 정상이고, 서버 처리(앱 로직, DB 쿼리, 업스트림 호출)가 느린 것을 의심한다.
